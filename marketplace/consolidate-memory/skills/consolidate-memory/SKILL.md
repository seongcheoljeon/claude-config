# Memory Consolidation

목표: 미래 세션이 다시 묻지 않고 빠르게 파악할 수 있는 메모리 상태 — 사용자가 누구인지,
무엇에 집중하는지, 어떻게 일하길 원하는지.

메모리 디렉토리·파일 형식·타입(user/feedback/project/reference)은 시스템 프롬프트의
메모리 섹션 정의를 따른다. 이 스킬은 절차만 제공한다.

## Phase 1 — 현황 파악

- 메모리 디렉토리를 나열하고 인덱스(`MEMORY.md`)를 읽는다.
- 각 파일을 훑으며 표시한다: **겹치는 것**, **낡아 보이는 것**, **내용이 얇은 것**.
- 인덱스에 없는 파일, 파일이 없는 인덱스 줄(깨진 링크)을 찾는다.

## Phase 2 — 검증

- 낡았다고 표시한 사실은 삭제 전에 **확인한다**: 파일/함수/플래그를 언급하면 아직
  존재하는지 조회하고, 프로젝트 상태를 언급하면 git 이력·코드와 대조한다.
- 상대 날짜("최근", "지난주")는 절대 날짜로 바꾼다.
- 확인 불가한 것은 지우지 말고 본문에 `(미확인, YYYY-MM-DD 기준)` 표기를 남긴다.

## Phase 3 — 정리 실행

- **병합**: 같은 주제를 다루는 파일은 하나로 합치고 나머지는 삭제. 병합본의
  frontmatter `description`을 합쳐진 범위에 맞게 갱신.
- **수정**: 틀린 사실은 고치고, 끝난 프로젝트의 진행상황성 메모리는 결론 한 줄로 압축.
- **삭제**: 더 이상 참일 수 없는 것, repo/CLAUDE.md가 이미 기록하는 것.
- **연결**: 관련 메모리 간 `[[name]]` 링크를 보강한다.

## Phase 4 — 인덱스 재작성

- `MEMORY.md`를 실제 파일 목록과 1:1로 다시 맞춘다 — 한 파일 한 줄, 훅(hook) 문구는
  그 메모리를 열어볼지 판단할 수 있게 구체적으로.
- 삭제/병합된 파일의 줄은 제거, 새 파일은 추가.

## 완료 보고

변경 요약을 표가 아닌 짧은 문장으로: 병합 N건, 수정 N건, 삭제 N건과 각각의 이유 한 줄.
확인이 필요해 남겨둔 항목이 있으면 명시한다.

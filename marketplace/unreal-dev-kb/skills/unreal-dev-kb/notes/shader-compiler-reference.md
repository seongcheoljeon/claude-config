## Part 1: 시나리오별 cvar 추천

### 셰이더 작업 시작 시 (셋업)

```ini
; 셰이더 디버깅 친화적 셋업
r.ShaderDevelopmentMode=1            ; 어설션/검증 활성화 (개발 모드)
r.Shaders.Optimize=0                 ; 최적화 끄기 — Nsight/RenderDoc에서 변수 검사 가능
r.Shaders.Symbols=1                  ; 플랫폼 셰이더 심볼 생성 + 디스크 기록
r.Shaders.GenerateSymbols=1          ; 심볼 데이터 생성만 (디스크 기록 X)
r.Shaders.WriteSymbols=1             ; 디스크에 심볼 기록만
r.Shaders.AllowUniqueSymbols=1       ; 소스 파일 기반 고유 심볼

r.ShaderCompiler.RecompileShadersOnSave=1 ; 셰이더 파일 저장 시 자동 재컴파일
```

### r.Shaders.Symbols vs r.Shaders.GenerateSymbols vs r.Shaders.WriteSymbols

UE5에서 셰이더 심볼 제어가 3개 cvar로 분리됨:

- **`r.Shaders.Symbols`** = `GenerateSymbols + WriteSymbols` 합성. 둘 다 켜는 편의용.
- **`r.Shaders.GenerateSymbols`**: 컴파일 시 심볼 데이터 **생성만**. 디스크 기록 X.
- **`r.Shaders.WriteSymbols`**: 이미 생성된 심볼을 **디스크에 기록만**. 생성 X.

이 분리는 "DDC에는 심볼이 들어 있는데 디스크엔 없다" 상황 때문. `Symbols=0`이지만 `GenerateSymbols=1`로 생성만 하고 나중에 `WriteSymbols=1`로 별도 추출 가능.

### r.DumpShaderDebugInfo vs r.ShaderCompiler.DebugDump*

두 계열은 **출력 위치와 트리거가 다름**:

- **`r.DumpShaderDebugInfo`** (글로벌 enum): 0/1/2/3. **모든** 컴파일 잡의 전처리 소스 + 명령줄 등을 `Saved/ShaderDebugInfo/`로 덤프. 매우 무겁다.
- **`r.ShaderCompiler.DebugDump*`** (개별 bool): `r.DumpShaderDebugInfo`로 덤프 디렉토리가 만들어진 잡에 대해서만 추가 정보(InputHash, Diagnostics, ShaderCode.bin, PlatformHash, DetailedShaderSource)를 같이 떨군다.

즉 `DebugDump*`는 `DumpShaderDebugInfo`의 보조 — 단독으로 켠다고 출력 안 나옴.

### r.PSOPrecaching vs r.ShaderPipelineCache

두 시스템은 **서로 다름**:

- **`r.ShaderPipelineCache.*`** (구버전, "PSO Cache"): PSO 사용 패턴을 빌드 시 기록한 `.upipelinecache` 파일을 출시 시 함께 배포 → 첫 실행 때 PSO 미리 빌드. **빌드/쿠킹 시 데이터 수집 필요**.
- **`r.PSOPrecache.*` / `r.PSOPrecaching`** (UE5 신규): 머터리얼/메시 컴포넌트 로드 시점에 **자동으로** 필요한 PSO를 사전 생성. 데이터 수집 불필요.

일반적으로 두 시스템을 **함께** 사용 — PSO Precaching이 신규 패턴을 잡고, ShaderPipelineCache가 검증된 패턴을 미리 컴파일.

### r.Shaders.ForceDXC vs r.D3D.ForceDXC

- **`r.Shaders.ForceDXC`**: **모든 플랫폼**의 모든 셰이더를 DXC 사용 강제 (per-platform ini 값).
- **`r.D3D.ForceDXC`**: **D3D 셰이더만** DXC 사용 강제. 결과 셰이더는 D3D12 전용 (D3D11 비호환).

### r.PSOPrecache.Mode

정수 enum (0~3 정도) — 단순 on/off 아님. 코드 확인 필요 (PSOPrecache.cpp 참조).

### Ref→global cvar의 "기본값"

표에서 `Ref→global` 타입의 "기본값" 컬럼은 **바인딩된 전역 변수 이름**임 (예: `GShaderCompilerAllowDistributedCompilation`). 실제 기본값은 해당 전역의 초기값을 코드에서 확인 필요. `static int32 GShaderCompilerAllowDistributedCompilation = 1;` 같은 형태.

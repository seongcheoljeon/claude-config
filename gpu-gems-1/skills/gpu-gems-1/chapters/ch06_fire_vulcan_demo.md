# Chapter 6: Fire in the "Vulcan" Demo
> 저자: Hubert Nguyen (NVIDIA)

## 핵심 개념
- **해결하려는 문제**: 대규모의 사실적인 불꽃과 연기를 실시간으로 렌더링 (GeForce FX 5900 Ultra 데모, 반지의 제왕 발록 영감)
- **애니메이션 스프라이트 방식**: 프로시저럴이나 파티클 대신, 미리 렌더링된 불꽃 애니메이션을 볼륨 텍스처에 저장하고 빌보드로 재생
- **3가지 접근법 비교**: 순수 프로시저럴 (비쌈), 2D 왜곡 기반 (제한적), 애니메이션 스프라이트 (채택)
- **알파 블렌딩 vs 애디티브 블렌딩**: 알파 블렌딩이 색상 제어와 불꽃-연기 혼합에 유리 (정렬 비용은 무시 가능)
- **열 아지랑이(Heat Haze)**: 화면 왜곡 효과로 불의 열기를 표현

## 기술적 세부사항

### 3가지 접근법 비교
1. **순수 프로시저럴**: 메모리 적지만 수천 파티클 필요 → CPU/GPU 부하 과다
2. **2D 왜곡 기반**: 촛불 같은 작은 불꽃에 적합하지만 대규모 화염엔 부족. render-to-texture 필요.
3. **애니메이션 스프라이트 (채택)**: 오프라인 렌더링된 불꽃 시퀀스를 텍스처에 저장, 빌보드 파티클로 재생

### 애니메이션 스프라이트 구현
1. **불꽃 생성**: 3ds Max + AfterBurn 플러그인으로 사실적 불꽃 애니메이션 렌더링
2. **볼륨 텍스처 저장**: 256×256×256 B8G8R8A8 압축 텍스처 (16MB)
   - z 좌표 증가 = 애니메이션 재생
   - 프레임 간 자동 보간(trilinear filtering)으로 부드러운 전환
   - 저사양: 64×64×256까지 축소 가능
3. **이미터 배치**: 모델링 툴에서 캐릭터 위에 이미터 배치, 크기/밀도/수명 등 조절
4. **파티클 시스템**: 이미터에서 파티클 스폰 → 빌보드 → 볼륨 텍스처 재생

### 블렌딩 전략
- **애디티브 블렌딩**: 정렬 불필요하지만 색상 포화 → 만화적 외관
- **알파 블렌딩 (채택)**: 정렬 필요하지만 사실적 색상 + 불꽃/연기 자연스럽게 혼합
- 수백 파티클 정렬의 성능 비용은 무시할 수준

### Heat Haze (열 아지랑이)
- 불꽃 주변 화면을 왜곡해 열기 표현
- 화면을 텍스처로 캡처 → 왜곡 맵(perturbation map)으로 UV 오프셋 → 재렌더링
- 프레임버퍼 전체를 복사하므로 비용 있음

```hlsl
// Heat Haze UV 왜곡
float2 perturbation = tex2D(perturbMap, uv + time * scrollSpeed).rg * 2 - 1;
float2 distortedUV = screenUV + perturbation * distortStrength;
float4 sceneColor = tex2D(sceneBuffer, distortedUV);
```

### 파티클 시스템 파라미터 설계
| 파라미터 | 불꽃(Fire) | 연기(Smoke) |
|---------|-----------|------------|
| 스폰 레이트 | 높음 (30~60/s) | 낮음 (5~15/s) |
| 수명 | 짧음 (0.3~1.0s) | 김 (2~5s) |
| 초기 속도 | 빠름 (위로) | 느림 (위로+확산) |
| 크기 변화 | 약간 커짐 | 크게 팽창 |
| 알파 | 밝게→페이드아웃 | 서서히 페이드아웃 |
| 블렌드 모드 | Additive 가능 | Alpha 필수 |

### 성능 고려사항
- 볼륨 텍스처(256³) = 16MB → VRAM 부담이 있으므로 LOD별 해상도 조절 필요
- 파티클 정렬은 CPU 기반 — 수천 개 이상이면 GPU 기반 정렬(bitonic sort) 고려
- 오버드로우가 핵심 병목: 큰 빌보드가 화면을 많이 차지할수록 fill rate 소비 증가
- 최적화: 작은 파티클 여러 개보다 적절한 크기의 파티클 + 좋은 텍스처가 효율적

## 수식 및 알고리즘

**볼륨 텍스처 애니메이션:**
```
texcoord.xy = billboard UV (0~1)
texcoord.z = (currentTime - spawnTime) / lifeSpan  // 0~1로 정규화
color = tex3D(flameVolume, texcoord)
```

**알파 블렌딩 (back-to-front 정렬 후):**
$$C_{dst} = C_{src} \times \alpha_{src} + C_{dst} \times (1 - \alpha_{src})$$

**알고리즘 흐름:**
1. 이미터에서 파티클 스폰 (위치, 속도, 수명 할당)
2. 파티클 업데이트 (이동, 수명 감소, 소멸)
3. 카메라 거리 기준 back-to-front 정렬
4. 각 파티클을 빌보드로 렌더링, 볼륨 텍스처에서 해당 프레임 샘플링
5. 알파 블렌딩으로 합성
6. (선택) Heat Haze 후처리 패스

## UE5 관점에서의 활용
- **Niagara VFX**: UE5의 Niagara 시스템은 이 챕터의 파티클+스프라이트 접근법을 훨씬 발전시킨 형태. GPU 시뮬레이션, 스프라이트/메시/리본 등 다양한 렌더러 지원.
- **Flipbook Animation**: 볼륨 텍스처 대신 SubUV(flipbook) 텍스처가 표준. 원리는 동일.
- **Screen Distortion**: Heat Haze는 UE5의 Post Process Material로 구현. Refraction/Scene Color 노드 활용.
- **현대적 대안**: 볼류메트릭 렌더링(ray marching), 유체 시뮬레이션(Embergen → VDB import)이 더 사실적이지만 비용 높음.

## 핵심 요약 (3줄)
- 오프라인 렌더링된 불꽃 애니메이션을 볼륨 텍스처에 저장하고 빌보드 파티클로 재생하는 실용적 기법이다.
- 알파 블렌딩 + 파티클 정렬로 불꽃과 연기의 자연스러운 합성을 달성했다.
- 이 "사전 렌더링 스프라이트" 접근법은 현대 VFX 시스템의 flipbook 파티클의 직접적 선조다.

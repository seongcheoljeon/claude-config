# Chapter 21: Real-Time Glow
> 저자: Greg James (NVIDIA), John O'Rorke (Monolith Productions)

## 핵심 개념
- **해결하려는 문제**: 전통적 LDR 그래픽스의 평면적 외관을 극복하고, 강렬한 광원과 발광 오브젝트의 글로우/할로 효과를 실시간으로 렌더링하는 것. *Tron 2.0* 게임에서 60fps 이상 유지하며 전체 화면 글로우 구현
- **핵심 아이디어**:
  1. **포스트 프로세싱 파이프라인**: 씬을 정상 렌더링 후, 글로우 소스만 별도 텍스처로 추출 → 블러 → additive 블렌딩
  2. **Separable Convolution**: 2D 컨볼루션(d² 비용)을 수평/수직 두 1D 패스로 분리(2d 비용). 50×50 블러: 2500 → 100 텍셀 읽기
  3. **저해상도 최적화**: 글로우 소스를 1/3~1/4 해상도로 렌더링. 블러가 고주파를 제거하므로 품질 손실 없음
  4. **알파 채널 기반 제어**: 텍스처의 알파 채널로 글로우 여부/강도 지정. `RGB × alpha`가 글로우 색상/세기
  5. **DX7~DX9 폴백**: 하드웨어 세대에 따른 점진적 구현 (고정 기능 → ps.1.3 → ps.2.0)

## 기술적 세부사항

### 전체 파이프라인
1. **글로우 소스 지정**: 텍스처 알파 채널로 마킹. 정점/오브젝트별 멀티플라이어로 시간 기반 애니메이션
2. **글로우 소스 텍스처 생성**: 두 가지 방법
   - 전체 씬을 다시 렌더링 (글로우 오브젝트만 컬러, 나머지 검정) — 비용 큼
   - `StretchRect`로 백버퍼를 텍스처에 복사 + 해상도 축소 (권장)
3. **수평 블러 패스**: 글로우 소스 텍스처 입력 → 1D 수평 커널 적용 → 중간 텍스처 출력
4. **수직 블러 패스**: 수평 블러 결과 입력 → 1D 수직 커널 적용 → 최종 글로우 텍스처
5. **합성**: 백버퍼에 글로우 텍스처를 screen-aligned quad로 additive 블렌딩

### Separable Convolution 원리
- 표준 2D: $O(d^2)$ — 50×50이면 픽셀당 2,500번 텍셀 읽기
- Separable: $O(2d)$ — 50+50 = 100번으로 동일 결과
- 가우시안 블러가 대표적인 separable 필터

### DX9 (ps.2.0) 구현
**Vertex Shader**: 8개 이웃 샘플링 좌표를 오프셋 상수로 계산
```asm
vs.2.0
dcl_position v0
dcl_texcoord v3
mov oPos, v0
add oT0, v3, c0  // 8개 이웃 좌표
add oT1, v3, c1
...
add oT7, v3, c7
```

**Pixel Shader**: 8개 이웃 샘플 × 커널 가중치 → MAD 누적
```asm
ps.2.0
texld r0, t0, s0
mul r0, r0, c0      // 첫 샘플 × 가중치
texld r1, t1, s0
mad r0, r1, c1, r0  // 두 번째 샘플 누적
...
mov oC0, r0
```

### DX8 (ps.1.3) 구현
- 패스당 4개 샘플만 가능 → 멀티 패스 + additive 블렌딩으로 누적
- 각 패스가 4개 이웃 샘플, 가중치 곱, 누적

### DX7 (고정 기능) 구현
- 동일 위치의 풀스크린 쿼드를 여러 장 스택
- 각 쿼드의 텍스처 좌표 = 이웃 샘플 위치
- 정점 컬러 = 커널 가중치
- `SetTextureStageState()`로 텍스처 × 정점 컬러 곱셈
- additive 블렌딩으로 스택 합성

### 실무 고려사항
- **앨리어싱 완화**: 저해상도(256×256) 글로우 텍스처에서 원거리 발광 지오메트리가 깜빡임 → 글로우 전용 검은 안개로 원거리 기여를 감쇠
- **DX7 정밀도 수정**: 0~255 정수 양자화로 인한 반올림 오차 → 잔여 오차를 다음 가중치에 누적
- **잔상 효과**: 이전 프레임의 글로우 텍스처를 감쇠시켜 현재 프레임에 더하면 streaking 효과
- **변수 램핑**: 커널 가중치와 안개 파라미터를 프레임마다 변경하여 동적 효과 (맥동 글로우, 분위기 변화)

### D3D 텍셀 오프셋 주의
Direct3D는 정확한 텍셀 중심 샘플링을 위해 0.5 텍셀 오프셋이 필요. OpenGL은 불필요 (좌표 규약 차이).

## 수식 및 알고리즘

### Convolution 비용
$$\text{Standard 2D}: O(d^2) \quad \text{Separable}: O(2d)$$

### Separable 필터 분해
$$G_{2D}(x, y) = G_{1D}(x) \times G_{1D}(y)$$

### 글로우 색상
$$\text{glow\_color} = \text{RGB} \times \alpha \times \text{per\_vertex\_multiplier}$$

## UE5 관점에서의 활용

- **UE5 Bloom**: 이 챕터의 기법이 직접 발전한 것. UE5의 Bloom은 다중 해상도 다운샘플 + 가우시안 블러 + 업샘플 합성
- **Separable Blur**: UE5의 모든 포스트 프로세스 블러(Bloom, DOF, Gaussian Blur)가 separable 컨볼루션 사용
- **저해상도 처리**: UE5도 Bloom을 1/2, 1/4, 1/8... 해상도에서 처리하여 성능 최적화. 동일한 원리
- **HDR 파이프라인**: 이 챕터는 LDR 시대의 기법이지만, HDR에서의 Bloom은 밝기 임계값(threshold) 기반으로 글로우 소스를 추출 — 알파 채널 대신 밝기값 사용
- **현대적 대안**:
  - FFT Bloom: 매우 넓은 글로우를 주파수 도메인에서 처리
  - Convolution Bloom: 커스텀 커널(렌즈 플레어 등)을 지원
  - UE5의 r.Bloom.Method로 Standard/Convolution 선택 가능

## 핵심 요약 (3줄)
- Real-Time Glow는 씬에서 글로우 소스를 추출하고, separable 가우시안 블러(2D를 1D×2로 분해)로 블러한 뒤 additive 합성하는 포스트 프로세스 기법이다
- 저해상도 처리, 멀티패스 폴백(DX7~DX9), 알파 기반 제어, 잔상 효과 등 실용적인 게임 구현 노하우를 담고 있다
- 이 기본 파이프라인(추출→블러→합성)은 20년이 지난 지금도 UE5 Bloom을 포함한 거의 모든 실시간 글로우 구현의 뼈대로 사용된다

**규칙**
1. 요구사항 / 범위 / API 버전 / 의도 중 **하나라도 애매하면 반드시 먼저 질문** 한 뒤 진행.
2. "가장 그럴듯한 해석" 으로 넘겨짚지 말 것. 코드 작성/답변 전에 **멈추고 확인**.
3. 추측으로 진행 금지.
4. 파일 Read/Write 시 **UTF-8 인코딩 유지**.
5. **복잡한 작업에서는 plan mode를 먼저 제안**하고 사용자 승인 후 진행.
6. Google Drive, 웹 검색 등 **액세스 가능한 모든 도구를 적극 활용**. 도움이 될 도구가 있으면 망설이지 말고 사용.

**Why:** 잘못된 가정 위에 쌓인 코드는 리팩터링 비용이 크고, 그래픽스 코드는 특히 디버깅이 어렵기 때문. 한글/주석 포함된 파일이 많아 인코딩 손상 시 복구가 번거로움. plan mode는 복잡한 작업에서 방향 정렬 비용을 줄임.

**How to apply:** 새 작업 시작 시 체크리스트로 "요구사항·범위·버전·의도" 4가지를 점검. 불명확 항목이 있으면 AskUserQuestion 또는 직접 질문. 파일 수정 시에는 기존 인코딩을 보존 (BOM 여부 포함). 여러 파일/시스템에 걸친 작업은 EnterPlanMode 제안 후 승인받아 진행. 검색·문서·Drive 등 가용 도구는 적극 사용.
